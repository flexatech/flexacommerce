# Benchmark baseline 2026-10-24 (phase 2.5)

First run of the T3 stack (doc 10 §5.3). It sets the baseline for the two scenarios that exist today, a blog post and the home page, and it checks that the tooling works end to end. Raw data: [`2026-10-24/S-php8.2-1vu/`](2026-10-24/S-php8.2-1vu/).

**Status of the numbers.** Per-request counters (queries, peak memory, rows read, worker RSS, HTML bytes) are deterministic and are the result of this run. Latency is **not valid** under the doc 10 rule: the spread of the run p95s is 22 to 69 %, far above the 10 % limit, because the machine was not quiet (below). The latency columns are printed so the method can be checked, and must not be quoted.

| WooCommerce | 11.2.1, default configuration as installed (HPOS on), with coming-soon mode turned off |
| Dataset | S, seed 42: 1,000 products (304 variable, 1,824 variants), 5 × 3 categories, 30 tags, 3 attributes. Spec sha1 `f7b3e713acf31d8f2aec64cb572fff698ed9ad10`. No orders or customers yet (phase 4). |
| Parity | `flexacommerce: parity OK (1000 products, 1824 variants)`, `woocommerce: parity OK (1000 products, 1824 variants)` |

Stores: **core** is the FlexaCommerce database with every plugin off, **fxc** is FlexaCommerce, **wc** is WooCommerce. Each store has the same blog post (`/benchmark-post/`) and the default WordPress content.

## Parity note

- The FlexaCommerce stores add nothing to these pages: no assets, no markup, no cookies. The home page has no product collection yet (that block is phase 5), so the home scenario here is the latest-posts home, not the doc 10 §6.4 homepage scenario.
- WooCommerce adds 5 stylesheets and 12 script tags (jQuery and jQuery Migrate among them), and its installer creates the Shop, Cart, Checkout and My account pages, which the Twenty Twenty-Five header lists through the page-list fallback. So the WooCommerce rows include rendering four more header links.
- WooCommerce ran in its default configuration only. The tuned configuration (doc 10 §6.3) is not part of this baseline.
- None of this compares commerce performance. FlexaCommerce has no storefront, cart or checkout yet, so it does far less work. What the table measures is the fixed cost each plugin adds to a page that has no commerce content.

## What this run supports

- P1 holds under PHP-FPM as well as in the T1 harness: 0 extra queries, 0 extra rows read, +63 KB peak memory (T1 budget 256 KB), no assets.
- Datasets S and M load natively into both stores and pass the parity check (M: 10,000 products, 36,828 variants, spec sha1 `b15f94015f7a7dcf807e01591d33d35978e7e654`). Load time on this machine: S 10 s FlexaCommerce, 72 s WooCommerce; M 117 s and 1,380 s. These are loader times through each plugin's write API, recorded as tooling cost; they are not a benchmark of the two plugins.
- The pipeline (warm-up separation, request-id join, spread check, MySQL and RSS deltas) works.

## What it does not support

- Any latency figure, including P1t (added server time ≤ 2 ms at p50). With run p50s moving by up to 9 ms between runs on this machine, a 2 ms effect cannot be resolved here. P1t stays reported, not gated (doc 10 §4.1), until the run happens on the reference machine.
- Page measurements on dataset M, 10 or 25 VUs, or a second PHP version. M is loaded and checked (`2026-10-24/parity-M.txt`, `2026-10-24/setup-M.txt`) but not measured; those runs need the reference machine too.

## Reproduce

```sh
cd tools/bench
./bench.sh up
./bench.sh setup S
./bench.sh run blog-post home
```
